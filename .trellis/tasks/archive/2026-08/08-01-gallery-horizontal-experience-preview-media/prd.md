# Gallery 横向摄影集体验与京都预览素材

## 目标

把 `/gallery/[slug]` 从用于验证内容模型的纵向图片骨架，升级为视觉优先、克制且可完整静态导出的横向摄影集体验；同时为现有“京都秋行”生成一套原创、统一且能真实检验横向/竖向/近方形布局的本地预览照片。

本任务是独立任务，不重新打开或挂靠已归档的 `06-18-site-direction-architecture` 父任务。规划经开发者确认并执行 `task.py start` 前，不修改业务代码或媒体。

## 用户价值

- 让照片集详情页具有明确的摄影集浏览节奏，而不是普通文章中的图片列表。
- 桌面和移动端都能使用各自自然的输入方式连续看图。
- 默认画面由照片主导，说明文字可被发现但不打断观看。
- 用风格统一且比例多样的真实预览素材验收交互，而不是继续依赖占位图片。

## 已确认事实与约束

- 当前详情页是 Server Component，构建期读取并校验 `content/gallery/*.yaml`，通过 `generateStaticParams()` 支持 Next 静态导出。
- 当前 Gallery schema 已包含本任务需要的 `src`、真实 `width` / `height`、`alt`、可选 `caption` / `note`；页面只消费 zod 校验后的 TypeScript 数据。
- 当前“京都秋行”有 5 张本地 JPEG 占位图，已经覆盖横向、竖向和方形比例，但内容与画质仅用于骨架验证。
- 全局 Header 固定在根布局中，当前没有页面级隐藏协议；Header 下方的 `<main>` 统一保留 `--header-height` 顶部空间。
- 全站只暴露 Light / Dark，`next.config.ts` 使用 `output: "export"` 与 `images.unoptimized: true`，运行时不能依赖图片优化服务或服务器接口。
- 主工作区可能有依赖 `.next` 的长期开发服务；禁止在主工作区运行 `pnpm build`，静态构建必须在排除 `.git`、`node_modules`、`.next`、`out` 的 `/tmp` 副本中进行。
- 仓库目前没有 Gallery 专用设计稿；`design/Selection.png` 不是本页面参考。
- 开发者确认没有尚未附上的 Gallery 设计稿或参考图；本任务以归档交互决策、现有站点 Light/Dark 气质和 `design.md` 的原创横向方案作为高保真视觉验收基线。
- 开发者希望生成符合 Gallery 影集气质的摄影照片，直接替换当前页面中的纯色占位图片，而不是保留占位素材或使用外部下载图片。

## 功能需求

### 横向浏览

- `/gallery/[slug]` 默认呈现单一横向浏览舞台，不再纵向铺开全部图片。
- 图片保持完整宽高比，不做不可预期的裁切；横向、竖向和近方形照片均应有稳定尺寸与视觉重心。
- 使用滚动吸附让一张照片稳定成为当前活动照片；首张与末张也能正确居中。
- 当前照片清晰、完整；左右相邻照片在视口边缘露出少量内容并降低透明度，提示可继续浏览。
- 桌面指针悬停相邻照片时只做轻微放大与提亮，点击相邻照片可将其滚入活动位置；动效不得造成布局跳动。
- 提供克制的当前位置提示；不让大面积箭头、标题或说明遮挡照片。

### 输入方式

- 桌面触控板的横向手势可原生浏览；常规鼠标纵向滚轮在摄影集舞台内映射为横向移动。
- 焦点位于摄影集时，`ArrowLeft` / `ArrowRight` 切换相邻照片；补充 `Home` / `End` 到达首尾。
- 移动端保留原生左右滑动与惯性，不实现自定义拖拽模拟。
- 到达横向首尾时不继续吞掉反方向/向外的纵向滚动，使用户仍能离开舞台或进入文字区。
- `prefers-reduced-motion` 下取消平滑滚动、缩放和 Header 位移动画，但保留吸附、可见状态与所有输入能力。

### Header 与浏览状态

- 首次进入详情页时 Header 可见，保留站点定位与返回路径。
- 用户产生横向滚动、方向键、点击相邻照片或触摸浏览意图后进入“专注浏览”状态，Header 向上隐藏且不改变照片布局。
- 打开文字详情、按 `Escape`、把指针移到页面顶部恢复区或焦点进入 Header 时，Header 重新出现；再次浏览时可继续隐藏。
- 离开 Gallery 详情页后，Header 必须恢复默认可见状态，不能影响其他路由。

### 文字与辅助信息

- 默认摄影集舞台不显示标题、摘要、caption 或 note；只保留低干扰的计数和详情入口。
- 提供明确但克制的“查看文字”入口，并支持 `ArrowDown`；展开后进入舞台下方的详情区域，而不是翻转图片或在图片上覆盖大段文字。
- 详情区域展示照片集标题、日期、摘要，以及当前活动照片的 caption / note；缺少可选字段时不显示空占位。
- 详情入口使用原生按钮，并通过 `aria-expanded` / `aria-controls` 表达状态；摄影集与每张照片具有可理解的无障碍名称和位置语义。
- 关闭详情或回到舞台后，键盘焦点回到合理位置，不产生焦点陷阱。

### “京都秋行”原创预览素材

- 用内置 `imagegen` 默认模式生成 7 张彼此一致的原创纪实旅行摄影作品，替换现有 5 张占位图。
- 系列基调：京都深秋、低饱和暖红/赭石、自然阴天或金色时刻光线、安静克制、真实摄影质感；不得含文字、logo、水印，不模仿具名在世摄影师。
- 场景至少覆盖：高处木桥与枫林、竖向竹林、寺院池塘倒影、落叶石径、寺院建筑/局部、庭院细节、黄昏桥梁与远山。
- 比例组合覆盖横向、竖向和近方形，建议 3 张横向、2 张竖向、2 张近方形，以检验混合比例节奏。
- 每张生成结果都需人工视觉检查；选定结果移动到 `public/gallery/kyoto-autumn/`，转换为网页适用的本地静态资源，并记录准确像素尺寸。
- 更新 `content/gallery/kyoto-autumn.yaml` 的 `cover`、照片顺序、路径、尺寸、中文 alt、caption 与可选 note；Gallery 索引封面和详情首图保持一致。

## 兼容与质量要求

- 保持 `/gallery`、`/gallery/[slug]`、现有 YAML schema 与 loader 的兼容性；除非实现中发现无法回避的契约缺口，否则不扩展内容模型。
- 交互逻辑位于专用 Client Component；文件系统/YAML 读取继续留在 Server Component 和 `lib/gallery.ts`。
- 不引入轮播库、手势库、运行时接口、外部图片服务或 CDN。
- Light / Dark、桌面和移动端均需浏览器视觉验收；Gallery 之外的 Writing、Music、About 与全局导航行为不能回归。
- ESLint、TypeScript、`/tmp` 隔离静态构建必须通过；导出产物应包含 Gallery 详情页和全部新媒体。
- 最终完成/归档前需要开发者进行浏览器视觉验收。

## 非目标

- 不重设计 `/gallery` 索引页；只更新因封面路径变化而必须同步的内容。
- 不提供原图、高分辨率下载、全屏灯箱、缩放、自动播放或循环轮播。
- 不修改 Writing、Music、About 的产品设计。
- 不引入新的全局主题、Gallery 专属后端、CMS 或外部媒体托管。
- 不在 planning 阶段生成图片或修改业务代码。

## 验收标准

- [ ] 活动照片吸附居中，左右相邻照片有可辨但克制的边缘露出、低透明与 hover / focus 状态。

## 已解决的产品决策

- **视觉基准**：没有外部设计稿；采用本任务原创的横向摄影集设计，并以 `design.md` 中可量化的布局、状态、输入和浏览器矩阵验收。
- **素材来源**：使用内置 `imagegen` 生成 7 张风格统一的原创“京都秋行”摄影照片，替换现有 5 张纯色 JPEG 占位图；不使用网络下载摄影作品。
- **文字说明**：采用舞台下方的非覆盖式详情区。默认画面不显示标题、摘要、caption 或 note；用户通过克制的详情按钮、`ArrowDown` 或自然纵向下滑进入文字区，不使用覆盖照片的底部抽屉。
- **Header 时机**：首次进入 Gallery 详情页时 Header 保持可见；用户产生横向滚轮、滑动、方向键或相邻照片点击等浏览意图后隐藏。打开文字区、按 `Escape`、进入顶部恢复区或 Header 获得焦点时恢复。
